# Так и назвали

Самостоятельный сайт про необычные названия Беларуси: 94 места на карте, фотографии, оценки, отзывы, комментарии и гостевой паспорт путешественника.

**Работает без регистрации, без ChatGPT и без отдельного сервера.** Все данные размещаются в твоём Cloudflare: Workers + D1 + R2. Обычные посетители просто открывают ссылку.

## Самый простой запуск: из GitHub через браузер

[Разместить в Cloudflare](https://deploy.workers.cloudflare.com/?url=https%3A%2F%2Fgithub.com%2FFlinch1137%2Ftak-i-nazvali)

Репозиторий проекта: https://github.com/Flinch1137/tak-i-nazvali

1. Создай аккаунты [GitHub](https://github.com/signup) и [Cloudflare](https://dash.cloudflare.com/sign-up).
2. В Cloudflare открой **R2 Object Storage** и активируй R2. Потребуется платёжный метод. Бесплатная квота действует, превышение оплачивается.
3. Создай **публичный** репозиторий GitHub, например `tak-i-nazvali`. Загрузи туда **содержимое этой папки**: `package.json`, `wrangler.json`, папки `src`, `public`, `migrations`, `scripts`, `tests` и остальные файлы. Не загружай сам ZIP, `node_modules` или родительскую папку целиком.
4. Открой адрес `https://deploy.workers.cloudflare.com/` и укажи ссылку на свой репозиторий. Прямая ссылка строится так: `https://deploy.workers.cloudflare.com/?url=` плюс URL репозитория. Можно получить её командой `npm run deploy:button -- https://github.com/USER/REPO`, заменив USER/REPO на настоящий репозиторий.
5. В мастере разреши Cloudflare работать с выбранным репозиторием. Проверь параметры: команда сборки `npm run build`, команда публикации `npm run deploy`. Если мастер предлагает отдельную команду для предварительных версий, оставь публикацию предварительных версий выключенной на первом запуске: не подключай к ним рабочую базу.
6. Мастер должен создать ресурсы **DB** (база D1) и **BUCKET** (фото в R2), записать настоящие идентификаторы в `wrangler.json` и опубликовать сайт. Команда `deploy` применяет миграции до публикации.
7. Скопируй выданный адрес на `workers.dev`. Проверь его в приватном окне браузера: карта → место → «Я здесь был» → запись → перезагрузка → «Мой паспорт» → удаление своей записи.

Этот путь подготовлен по документации Cloudflare Deploy to Cloudflare. Настоящий облачный запуск требует твоего аккаунта и ещё не выполнен. Если мастер не сможет подготовить ресурсы, используй путь ниже.

## Запасной запуск с компьютера: одна команда настройки

Нужен Node.js 22.13+ (лучше актуальная LTS). Открой терминал в этой папке:

```sh
npm ci
npm run setup
```

Скрипт предложит войти в Cloudflare, найдёт или создаст D1, создаст R2 при необходимости, запишет настройки, применит миграции и опубликует сайт. Токены не надо вставлять в код или отправлять в чат. Если в аккаунте несколько рабочих пространств, выбирай нужное при входе. Для явного выбора можно задать `CLOUDFLARE_ACCOUNT_ID` в окружении своего терминала.

Если R2 не активирован, скрипт остановится с подсказкой. Активируй R2 в панели Cloudflare и запусти `npm run setup` ещё раз. Скрипт использует существующую базу с тем же именем и не удаляет данные.

## Последующие обновления

После первого запуска сохрани **обновлённый** `wrangler.json` с настоящим ID базы в GitHub. Там нет паролей или токенов.

В Cloudflare можно подключить автоматическую публикацию к репозиторию через Workers & Pages → свой Worker → Settings → Builds. Имя Worker должно соответствовать полю `name` в `wrangler.json`. Команда сборки: `npm run build`; публикации: `npm run deploy`.

Либо публикуй вручную:

```sh
npm run deploy
```

## Проверка и локальная разработка

```sh
npm ci
npm run check
npm test
npm run deploy:check
npm run dev
```

`npm run dev` применяет миграции только к локальной базе и запускает Wrangler. Локальные тесты используют отдельную базу и хранилище в памяти. `deploy:check` собирает Worker без публикации и без входа в аккаунт. Для местного просмотра открой адрес, напечатанный Wrangler.

## Как устроен проект

- `public/` — сайт, стили, Leaflet и каталог мест.
- `src/index.ts` — Worker, маршрутизация API и статических файлов.
- `src/community.ts` — гостевые публикации, фото, рейтинги и удаление собственных записей.
- `src/catalog.json` — допустимые ID мест для серверной проверки.
- `migrations/0001_community.sql` — схема базы, применяемая Wrangler один раз.
- `wrangler.json` — настройки Cloudflare. Нулевой UUID в исходной версии — явный шаблон; мастер Cloudflare или `setup` заменит его настоящим.
- `scripts/setup.mjs` — первоначальная настройка и запуск.
- `tests/community.mjs` — интеграционные проверки Worker, D1 и R2.

Если меняешь каталог, обновляй и `public/data.json`, и `src/catalog.json`. ID существующих мест должны сохраняться.

## Что важно знать

- Эта папка содержит код и каталог, **не выгрузку уже опубликованных пользовательских отзывов или фотографий**. Новый запуск создаёт свою базу. Предыдущий сайт продолжает работать отдельно.
- В этой версии аккаунтов нет. Cookie браузера позволяет управлять собственными публикациями. После удаления cookies доступ к управлению потеряется. Между разными доменами cookies не переносятся.
- Посещение указывается самим пользователем, а не подтверждается GPS. Рейтинг считает одну актуальную оценку гостевого браузера на место. Повторный визит не увеличивает число уникальных гостевых браузеров.
- Действует ограничение частоты публикаций для гостевого браузера. Проверяются фото JPG/PNG/WebP до 5 МБ и серверное право удаления записи. Полноценной модерации и защиты от массового создания новых гостевых браузеров пока нет.
- Оригинальные EXIF-метаданные фото удаляются пересохранением в браузере перед отправкой. Не публикуй чужие личные данные.
- Бесплатные квоты не означают отсутствие оплаты при росте проекта. Проверь условия [Workers](https://developers.cloudflare.com/workers/platform/pricing/), [D1](https://developers.cloudflare.com/d1/platform/pricing/) и [R2](https://developers.cloudflare.com/r2/pricing/) в своём аккаунте. Код не включает платный план автоматически.
- Дорожные указатели в дизайне остаются декоративными иллюстрациями; точное оформление реальных белорусских знаков требует отдельной правки.
- Своего домена не требуется: можно начать с адреса Cloudflare `workers.dev`.

## Резервные копии

Для базы:

```sh
npm run db:export
```

`backup.sql` исключён из Git. Это только база; фотографии R2 нужно сохранять отдельно. Экспорт в рабочей базе требует входа в твой Cloudflare.
